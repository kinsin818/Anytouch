3. **证据纪律**：raw 只追加（二进制模式 + 前缀哈希自证）；每段带时间戳与 RC；虚报即撤回报真账。

## §3 验收判据（"过/不过"逐条可对盘）

**S4-a：**
1. 全流程一条不漏，每步有屏上凭据（uiautomator dump 的 testTag 命中原文）或日志凭据：冷启动 → 授权在位 → 凭据行显示 `***尾4` → 编译 `compile ok steps=N` → 任务框建议与 `RecorderStore` 账逐字相等 → 执行回执 `ok/total` 真发生在目标 App。

3. 失败路径至少现场走通 1 档（如空意图拒/无凭据拒），屏上拒因=话术表原文，不抽查话术全表（那是 JVM 的账）。

5. 任一环节按既有判据红了：**停下、归因、照报**，不许改判据迁就读数（E1 Z-1 纪律）。

**S4-b：**
1. 话术里每一句"产品能做 X"都能指到磁盘行：evidence 段落、`STATUS.md` 条目或测试名。逐条列**背书表**（句子 → 凭据路径），无背书的能力句一律删除。

## §4 诚实边界与待裁项（开工前备案，不许事后洗）

1. **S4-R6 的"三模型共识"不在本单实施**：现编译面=单 BYOK 端点单次调用；三模型需要三把 Key/跨模型 Key、×3 token 成本、以及"输出一致"的可测对齐口径（逐字等？语义等？）。阈值 70% 作为**验收线即刻生效**，但矩阵（≥10 条真实意图）与共识机制需另立切片，实施前需老板对**对齐口径**与**供应商/Key 形态**各一句话。
2. **APP 内中文文案 vs 海外专供**（S3 单 §4-2 登记的冲突）：话术是英文的，屏是中文的，用户装完第一眼就是中文 UI——这矛盾 S4-a/b 都不解决，**要不要 localize 全量 UI 文案请老板一句话**（改动面大：testTag 不动、话术串集中处需盘点）。
3. **Gumroad 上架动作本身**（账号、定价、支付、素材图、分发协议）不属代码域，话术单只是弹药；老板自己上或另令。
4. debug APK 签名=debug keystore：话术必须如实写"sideload 的 debug 构建"，不许暗示正式签名/Play 保护。
5. E11 已把机上凭据真清；S4-a 用代填通道恢复，跑完若再跑 `E_WIPE=1` 又会清——两脚本互斥关系在证据里写清，避免下窗误读。
