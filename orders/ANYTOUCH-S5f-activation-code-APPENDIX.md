## 1. 编码细则（判据钉死，Kotlin 实现与 JVM 用例逐字对拍）

- **字符集**：正文 12 位只允许 `A-Z` 与 `0-9`（`ANY` 前缀除外）。输入统一 `trim` → 转大写 → 去掉内部空白后校验（粘贴容错），其余任何字符（含全角、连字符错位、下划线、小写以外的 Unicode 数字）一律拒。
- **形状**：去容错后必须严格匹配 `ANY-[A-Z0-9]{4}-[A-Z0-9]{4}-[A-Z0-9]{4}`，长度恰为 18。
- **校验位（裁 3）**：正文记 b1..b12（b1..b4=第一段，b5..b8=第二段，b9..b12=第三段）。
  - b11 = `chr(ord(b1) % 26 + 65)`，b12 = `chr(ord(b2) % 26 + 65)`，即**前两位逐位**取 ASCII 模 26 映射到 A-Z。
  - 军令原文"前两位字符ASCII**和**取模"读作"逐位各取模、共两枚校验字母"（裁 3 选的即此默认细则）。
  - 自由位=b1..b10（10 位，36^10≈3.6e15 组合），校验位不增加秘密性，只作**防手滑**：抄错一位有约 26 分之一的概率被当场认出。
- **拒因分档**（每档一句独立英文话术，单源见 `ActivationGate`）：`EMPTY` / `BAD_LENGTH` / `BAD_PREFIX` / `BAD_SEPARATOR` / `BAD_CHARSET` / `CHECKSUM`。
- **样例（golden，逐字进 JVM 用例）**：
  | 正文 10 位 | 完整码 |
  |---|---|
  | `A1B2C3D4E5` | `ANY-A1B2-C3D4-E5NX` |
  | `0000000000` | `ANY-0000-0000-00WW` |
  | `ZZZZZZZZZZ` | `ANY-ZZZZ-ZZZZ-ZZMM` |
  | `9A8B7C6D5E` | `ANY-9A8B-7C6D-5EFN` |
  | `PRO9FAN8B1` | `ANY-PRO9-FAN8-B1CE` |
  字母映射锚点：`A→N`、`Z→M`、`0→W`、`9→F`、`1→X`。
- **发卡工具**：`scripts/activation-code.py`（JVM 侧生成器 `ActivationCode.issue()` 的同号镜像，供老板出码与脚本取码）。两边同源同算法，golden 表在两侧都逐字断言，防止漂出第二份口径。

## 2. 门禁边界（三进墙、六绝不进墙）

**进墙（未激活即拒，且拒因必须上屏 + 留痕）**：
1. `REPEAT_LOOP` 重复循环——仅当**真动用**（repetitions ≥ 2）才拦；repetitions=1 的普通单发（含 interval 框里留着默认值）逐字不受影响。
2. `SAVED_TASKS` 我的任务——存/载/删/存档直跑四条通道同一口拦。
3. `MANUAL_STEP_INSERT` 手动补步骤——唯一写口 `applyEdit(StepEdit.Insert)` 前拦，"+ Step" 钮置灰只是提示。

**绝不进墙（一条都不许被本功能波及，写死为 JVM 锁）**：高危二次确认面板与 15 秒默认拒、停止球急停、执行期零网络、无障碍服务门禁（L1/L2）、AI 编译与 BYOK 配置、录制（开录/停止并编译）、三枚预制模板装载、任务派发与执行本身、失败重试判据（S5-e 裁①）、步序账的删/改名/移序、磁盘洁净化。
**理由（军令之外主窗自钉）**：付费墙不许改变任何一条安全语义——把"要不要问用户"绑进"买没买"是拿用户安全换营收；未激活用户仍要拿到与 v1.0.4 逐字相同的安全行为。

**UI 口径**：三处入口未激活时置灰并各挂一句含 **"Upgrade to Pro"** 的英文字样（军令第 3 条指定字样，单源一处，不许三处各抄一份）。
