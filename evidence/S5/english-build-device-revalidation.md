## 3 两处红账定性：都是裁判的缺陷，不是产品的缺陷（假红假绿同罪，先自曝）

**F-A 高危确认"盲投"（batch-1 轮 3/5 真因）。** 旧脚本对"确认执行"钮只做一件事：见自家窗回焦就
按标定坐标点一次，然后撒手。点空时产品行为完全正确——面板挂到 15s 超时默认拒，回执
`ok=8 total=9 stopped=true stop="DELETE:delete"` + `SAFETY_GATE_BLOCKED`（该两行落在 batch-1 轮 4 的
buffer 里，device 时戳 22:04:33.404，正是轮 3 的尾巴）。但账面只剩"回执不达"四个字，
**分不清"测试手指没点到"与"产品确认钮坏了"**——这是判据的无能，不是产品的失败。
修法（判据只加不减）：①面板在场瞬间 `exec-out screencap` 留证（只读，非 `uiautomator dump`，不打断在跑任务）；
②点完复核面板窗是否撤走，8s 内没撤=当场记红"首次确认点击未落"并补点一次让本轮链走完，
补点事实写进 RAW，不洗成"一次点中"。batch-2/3 五轮均无该红字=手指次次落。

**F-B 磁盘终判抢跑（batch-2 轮 1 假红，我自己引入）。** `ok=9` 落账在前、Photos/MediaProvider 把
`.trashed-*` 物理删除在后，中间有一段真实异步。旧脚本"点完 sleep 12"顺带吃到了这段沉降；
我改成"回执一出现即读"，就把这条设备事实变成了假红（读数 `trashed=2`，稍后再读已归零）。
修法：回执后固定 15s 沉降，再最多三次对拍（0/8/16s），每次读数带 device 时戳入 RAW；
**判据本身不松**——残留必须归零才记绿，只是不再把"删除在飞"当"删除失败"。batch-3 五轮全部第 1 读归零。

## 4 面板几何实证（英文文案会不会把确认钮挪走）

`s5a-panel-round3-061837.png` 逐像素看：面板三行正文
"High-risk action: DELETE:delete / matched field TEXT / Confirm and run it?"，
"Confirm and run" 因英文更长折成两行 → 面板比中文版更高、居中后按钮整体下移。
换算到本靶机：钮面约 x 550–818 / y 1230–1332，标定点击 (702,1294) 仍在钮面内，但**余量变小**
——这就是 batch-1 轮 3/5 漏点的物理解释。产品侧用户是目视点按，不受标定影响；
测试侧坐标沿用 killdemo 标定值未改（改了反而丢历史可比性），改由 F-A 的撤窗复核兜住。

**待裁（不擅动）**：面板正文 `High-risk action: DELETE:delete` / `matched field TEXT` 是工程黑话，
$6.99 的海外付费用户看着像调试框。军令第 ① 条要"地道英文"，这句严格说没达标；
但它同时是安全闸的唯一上屏归因（历账靠它和日志逐字对拍）。建议 v1.0.2 人性化改写
（例："This step may permanently delete items. Run it once?" + 小字保留规则 id），
改则需重打 APK + 重扫 + 重跑五轮（约 20 分钟）。本批按"已验证字节不动"交付 v1.0.1。

## 5 过程事实（另记两三条）

- **F-C "已杀"通知再次骗人**：batch-2 我用 TaskStop 停后台跑，通知说 stopped，但脚本子 bash（pid 135374）
  仍活着并持有 S0b 独占锁，导致 batch-3 首启被自家锁拦下（`RAW_EXIT=2`，预检正确 fail-closed）。
  `kill -9` 该 pid 后复跑。教训沿用：**上跑未落地禁止放下跑**，锁拦人时先查锁主死活，不删锁文件赌运气。
- **F-D host 与设备时钟差 1–2s**：RAW 内每轮双时戳实测（如 host=06:22:45 / device=22:22:44）。
  读时线以 device 为准；batch-1 我一度据此推出"回执早于点击"的悖论，就是拿 host 秒对 device 毫秒。
- 中止的 batch-2 在设备上留下 `.trashed-*S5SEEDR4*` 两具残骸（测试种子，本窗自造），
  复跑前用 `adb shell rm` 清干净并复核目录归零——不清则轮间全局计数判据会被上一批残骸冒充（历账同款雷）。
