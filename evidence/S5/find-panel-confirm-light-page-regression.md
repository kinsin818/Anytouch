# S5-d · 面板按钮检测器改面（浅色页根因）+ 26 张实截离线对拍

> 触发：`scripts/s5d-repeat-loop-smoke.sh` 的 L4/L5 两格把高危面板长在 **Settings 搜索页**（浅底），
> 旧版 `scripts/find-panel-confirm.py` 三拍全部量不到钮。本文件钉三件事：**根因、修法边界、逐张对拍账**。
> 身份：这是**测试通道**的读数器，不是产品代码；产品侧本轮零改动（军令第 6 条）。

## 1. 根因（不是阈值问题）

旧版口径："整屏找成块浅色带（>=60px 高），按列聚簇后恰好两簇 = 面板底部并排两枚 Material 浅灰按钮"。
这条默认了**页面底色是深的**（v1.0.1/v1.0.2 的宿主页是 Photos 黑底，浅色带只可能是按钮）。
浅底页上整屏每一行都是浅色带、带与带连成一片，"恰好两簇"永不成立。

run 3（09-25 11:31）逐字实录，`evidence/S5/raw/s5d-repeat-20260925-113101.raw.txt`：

```
no-two-button-band-found dark-panel-px=99295
```

`dark-panel-px=99295` 这一半是关键：**面板底色像素近乎满量＝面板确实在场**，
所以红的是读数器判据，不是"没拍到内容帧"（那一种是 v1.0.2 轮 4 的 `dark-panel-px=0`，两回事）。

## 2. 修法与边界

改成两级：① 先按面板底色（`0xF2212121` 半透明深灰）圈出**面板矩形**（最长深色行带 → 带内深色列带）；
② 只在矩形及其下方窗口里找底部那条浅色带，仍要求"按列聚簇后恰好两簇"，取右簇中心。

- **没有走"把阈值调松"这条路**：调松会在别的页面上把页面自身读成按钮 = 假命中，比假红更贵。
- 按钮行其实落在深色矩形**下沿之外**（面板底边到按钮有一截间距），所以扫描窗从矩形顶往下扩到
  `y1 + 2*(y1-y0) + 200`；这条是重写过程中第 3 个自错（见 §4）。
- 量不到仍非零退出，调用侧只准记红；退死坐标试投必须在 RAW 里显形（脚本里 `退死坐标试投——本格不记干净绿`）。

## 4. 重写过程中我自己被抓到的三处错（都由这张对拍表暴露，不是设备红）

1. `runs()` 把**计数**而不是**坐标**聚成簇 → 26 张全 `rc=1`；
2. `clusters()` 丢了 GAP 规则 → 左右两枚钮连成一簇 `(170,909)`，"恰好两簇"变"一簇"；
3. 扫描窗只到矩形下沿 `y1` → 按钮行在带外，浅页八张量不到。

三条都在离线对拍阶段红掉，未进任何设备轮；教训沿用：**改读数器必须先在历史实截上过对拍**，
设备面只用来发现"历史截屏里没有的那类页面"（本次的浅底页正是靠新格才发现）。

## 5. 遗留边界（在册不遮）

- 本版只在 1080x2400 的 avd34 截屏上对过拍；换分辨率未验（兜底坐标本就按宽高线性缩放）。
- 判据仍是"浅色 = 按钮"，若面板改成深灰按钮（Material 3 高对比主题）会退回 `rc=1`——
  那属于"如实记红"，不会假绿。
- `dark-panel-px` 只作**归因**（区分"没拍到内容帧"与"拍到了不认"），不作放行判据。
