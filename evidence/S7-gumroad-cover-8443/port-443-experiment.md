## 2. 为什么"不起监听"也拿得到这一格的答案

判据是 **SYN 到没到网卡**，不是"连没连上"。`tcpdump` 挂在 `enp1s0` 上、位于 netfilter **之前**：
- 端口**有**监听 → 抓到 SYN + 本机 SYN/ACK；
- 端口**无**监听 → 抓到 SYN + 内核回的 RST；
- 包被上游（Vultr 云防火墙 / DDoS 清洗 / 路由）丢掉 → **一个包都抓不到**。

所以"临时监听"对定性没有增益：它只把"SYN+SYN/ACK"和"SYN+RST"这两种**都能区分于零包**的情形再分一次。
真正要区分的"零到达 vs 到达但被拒"，无监听态就够判。win5 三端口同窗（22 / 443 / 8443）读数：

| 目的端口 | 到达包数（win5，08:36:34–08:41:34 UTC） | 说明 |
|---|---|---|
| 22 | 9 | 全部来自本施工窗 ssh 自己的出口 `209.248.0.98` |
| 443 | **0** | 该端口无监听（§1 已证），若探测真到达会看到 SYN+RST |
| 8443 | **0** | 该端口有服务在听（`ss` 两度证），若探测真到达会看到 SYN+SYN/ACK |

⇒ 三发外部探测（8443/443/22）在**同一台机、同一张网卡、同一个抓包窗**内**零到达**。
443 那发是**阴性对照**：它与 8443 一样零到达，而 443 上根本没有服务可拒——
这正好说明"零到达"这个读数与端口开没开**无关**，只与"探测包有没有被送到这台机"有关。

## 3. 结论口径与限制（不越界）

- 被动对照能证的：机内防火墙排除（`-P INPUT ACCEPT`，仅一条 `--dport 9000 DROP`，ufw-* 链全空）、
  服务在公网 IP 上活着（`ss-after.txt` 里自打 `https://45.32.63.177:8443/api/health` → `HTTP=200`）、
  第三方探测节点**从未把包送到这台机**。
- 被动对照**不能**证的：上游（Vultr 云防火墙 / DDoS 防护）**是否**按端口丢包 —— 因为唯一可用的外部视角
  （check-host.net 59 节点）对本靶已被证明**无效**：它对**正承载该工具自己那条 ssh 会话**的 22 端口报
  58/59 超时、对 ICMP 报 59/59 100% 丢包（详见 `probe-external.raw.txt` §1–§2）。
  一个连"确定通"的端口都测成红的尺子，量不出"8443 通不通"。
- 故 STATUS 待办 18 就地销的措辞取三选一里的第三条：**未定性，缺老板的手**
  （缺：Vultr 控制台该实例 Firewall/DDoS 页只读视图或 API Key；或一台走蜂窝的手机打一次 `/api/health`）。
  账面**不写**"已对全球买家可用"，也**不写**"端口被防火墙拦死"。
